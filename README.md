## 🧮 Что умеет калькулятор

Вкладка **«Ипотека»** с двумя режимами расчёта. Слева — параметры, справа —
результаты, внизу — графики и график платежей.

| Режим              | Вопрос, на который отвечает                                        |
| ------------------ | ------------------------------------------------------------------ |
| 🏷 **По стоимости** | Квартира стоит X, взнос Y — какой будет платёж и переплата?        |
| 💳 **По платежу**   | Я могу платить X в месяц — на какую стоимость недвижимости хватит? |

Параметры: стоимость или платёж, первоначальный взнос (в ₽ или в %, с
автоматическим пересчётом между единицами), ставка, срок (в годах или
месяцах), тип платежей, дата первого платежа.

Дополнительно:

- 📐 Аннуитетные и дифференцированные платежи
- 📊 Три графика: остаток долга и накопленные проценты, платежи по годам
  (долг + проценты), структура расходов (взнос / долг / проценты)
- 🧾 График платежей по годам и по месяцам, с реальными датами
- 💼 Необходимый доход (при доле платежа 40 %) и переплата в % от кредита
- 📄 Экспорт в **PDF** — параметры, итоги, векторные графики, таблица по годам
- 📊 Экспорт в **Excel** — сводка, помесячный график и годовая динамика;
  суммы — числа, а не строки
- ✅ Валидация на лету: подсветка поля и понятное сообщение об ошибке
- 🌗 Светлая и тёмная тема (по настройкам системы)

## 🧠 Математика

### Модель

Так считают банковские графики платежей в РФ:

```
i = ставка_год% / 100 / 12                 номинальная месячная ставка
проценты_за_месяц = round(остаток · i)     округление до копейки, half up

аннуитет:      A = S · i·(1+i)^n / ((1+i)^n − 1)       (i = 0 → A = S/n)
дифф., месяц k: платёж_k = S/n + остаток_{k−1} · i
```

Это **не** эффективная ставка `(1+r)^(1/12) − 1`, как в инвестиционном
калькуляторе: в ипотечных договорах проценты начисляются по номинальной
ставке/12, поэтому и здесь так.

### Обратная задача («по платежу»)

Для аннуитета платёж линеен по сумме кредита, поэтому максимальный кредит —

```
S = A · ((1+i)^n − 1) / (i·(1+i)^n)
```

Для дифференцированного графика целевой платёж — это **первый** (самый
большой): `S = P₁ / (1/n + i)`. Если взнос задан в процентах, максимальная
цена находится из `цена − взнос%(цена) ≤ кредит`.

На практике обе обратные задачи решаются не по формуле с плавающей точкой, а
**точно по копейкам**: ищется наибольшая `S`, для которой
`первый_платёж(S) ≤ цель < первый_платёж(S + 1)`. Банк гарантированно
выдаст кредит с платежом не больше заданного, и ни копейкой меньше возможного.

### Точность вычислений

- **Деньги — целые копейки**, ставка — рациональная дробь `p/q` на `BigInt`.
  `0.1 + 0.2` здесь всегда ровно `0.3`, а `(1+i)^n` считается точно:
  `((q+p)/q)^n` — целочисленное возведение в степень без накопления ошибки.
- Округление — **half up** до копейки на каждом шаге, как в банковских графиках.
  Последний платёж закрывает остаток ровно до копейки, поэтому он может
  отличаться от регулярного на пару рублей. Это нормальная банковская практика,
  а не ошибка: погрешность не превосходит `((1+i)^n − 1)/i` копеек и проверяется
  тестами.
- В дифференцированном графике основной долг раздаётся по месяцам формулой
  `⌊S·k/n⌋ − ⌊S·(k−1)/n⌋`: суммы месяцев отличаются максимум на 1 копейку,
  итог равен кредиту без остатка.
- Лимиты ввода (до 100 млрд ₽, срок до 50 лет, ставка 0–100 %) гарантируют,
  что все суммы помещаются в `Number.isSafeInteger`.

## ✅ Проверка кода

Математическое ядро проверяется на трёх уровнях:

| Уровень                 | Что проверяет                                                                                                     |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Golden-данные**       | Графики и обратные задачи сверяются до копейки с независимым эталоном на Python (`fractions.Fraction`), `scripts/gen_golden.py` |
| **Инварианты**          | 300+ случайных кейсов (ГПСЧ с seed): сумма долга = кредит, остаток → 0 ровно, остаток не растёт, платёж = долг + проценты, `платёж(S) ≤ цель < платёж(S+1)` |
| **Кросс-проверка float** | Аннуитет против формулы на `double` (погрешность < 1e-9)                                                           |

Плюс тесты валидации и граничных значений (0 %, 100 %, 1 месяц, 50 лет,
100 млрд ₽), экспорта (PDF собирается с кириллицей, Excel читается обратно и
суммы сходятся), дымовой тест UI в `jsdom` и статические проверки
(`id` уникальны, все подключённые файлы существуют). ESLint (flat config)
и всё перечисленное запускаются в GitHub Actions на каждый push и PR.

## 🛠 Стек

```
HTML5 · CSS3 · Vanilla JavaScript (без сборщиков и фреймворков)
BigInt     — точная арифметика денег и ставок
Chart.js   — графики (vendored, 4.5)
jsPDF      — PDF-отчёты (vendored, 4.2) + встроенный IBM Plex Sans для кириллицы и ₽
SheetJS    — Excel-отчёты (vendored, 0.18)
node:test · ESLint · jsdom — тесты и проверка кода (только для разработки)
```

Библиотеки лежат в `src/vendor/`, шрифты — в `src/fonts/`: проект работает
полностью офлайн, без CDN. Для запуска `npm install` не нужен — это статический
сайт. Модули — UMD-скрипты (без `import`), поэтому `index.html` открывается
даже по `file://`, а тесты подключают те же файлы через `require`.

## 🚀 Запуск

Проект не требует сборки — достаточно открыть `src/index.html` в браузере
или поднять любой статический сервер:

```
# вариант 1 — VS Code Live Server
# просто открой src/index.html правой кнопкой → "Open with Live Server"

# вариант 2 — Python
cd src && python3 -m http.server 8080

# вариант 3 — через npm-скрипт
npm run serve
```

Затем перейти на `http://localhost:8080`.

### Проверки

Нужен Node.js ≥ 22.13 (только для тестов и линтера):

```
npm install
npm run check      # eslint + все тесты
npm test           # только тесты
npm run lint       # только линтер
npm run golden     # пересобрать эталон (нужен Python 3)
```
